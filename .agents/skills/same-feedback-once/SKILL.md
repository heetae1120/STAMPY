# Same Feedback Once — 같은 피드백은 한 번만

AI가 같은 디자인 실수를 반복하는 건 기억할 곳이 없어서다. 이 스킬은 프로젝트 루트의 `DESIGN.md` 하나를 기억 장소로 쓰고, 세 가지 모드로 그 파일을 만들고, 지키게 하고, 키운다.

**원칙: 디자인 결정은 사람이 한다.** 이 스킬은 묻고, 검사하고, 제안할 뿐이다. 사용자가 승인하지 않은 규칙은 쓰지 않고, 검사·기억 모드에서는 화면이나 코드를 고치지 않는다.

사용자의 언어로 답한다 (기본: 한국어).

## 0. 모드 고르기

먼저 프로젝트 루트에 `DESIGN.md`가 있는지 확인한다.

| 상황 | 모드 |
|---|---|
| `DESIGN.md`가 없다, 또는 "규칙 만들어줘" | **1. 인터뷰** |
| "검사해줘", "위반 찾아줘", "AI 티 나는지 봐줘", 화면·URL·Figma 링크를 주며 확인 요청 | **2. 검사** |
| "오늘 작업 정리해줘", "고친 거 규칙으로", 세션 마무리 | **3. 기억** |

`DESIGN.md` 없이 검사나 기억을 요청받으면, 인터뷰부터 하자고 한 줄로 제안한다.

---

## 1. 인터뷰 모드 — 규칙은 AI가 쓴다

### 1-1. 먼저 읽고, 모르는 것만 묻는다
질문하기 전에 알아낼 수 있는 건 직접 알아낸다.
- 코드가 있으면: CSS 변수, Tailwind 설정, 테마 파일, 자주 쓰는 컴포넌트에서 색·폰트·간격·모서리 값을 뽑는다.
- Figma 링크가 있고 Figma MCP가 연결돼 있으면: 변수(Variables)와 스타일을 읽는다.
- 스크린샷이나 URL만 있으면: 눈에 보이는 색·폰트·간격을 추정하고 *(추정)* 표시를 한다.

### 1-2. 질문은 한 번에, 최대 7개
읽어서 알 수 없는 것만 묻는다. 예시:
1. 이 화면을 주로 쓰는 사람은 누구인가요?
2. 브랜드 느낌을 단어 3개로 말하면?
3. 꼭 써야 하는 색·폰트가 있나요? (예: Pretendard)
4. 절대 쓰지 말아야 할 것은? (예: 그라데이션, 이모지 아이콘)
5. 닮고 싶은 레퍼런스 서비스나 화면은?
6. 지켜야 할 접근성 기준이 있나요? (예: 글자 대비 4.5:1)
7. 그동안 AI한테 제일 자주 한 잔소리는?

7번 답은 그대로 첫 규칙 후보가 된다.

### 1-3. DESIGN.md 작성
`templates/DESIGN.md`의 구조를 따른다. 템플릿 파일이 없으면 이 구조로 쓴다: 맨 위 YAML(`colors`, `typography`, `spacing`, `radius`, `shadow` 토큰 값) → `## 개요`(누가 쓰나·브랜드 느낌·레퍼런스) → `## 색` → `## 글자` → `## 간격과 레이아웃` → `## 컴포넌트` → `## 접근성` → `## 하지 말 것` → `## 학습된 규칙`. 위쪽 YAML에는 토큰 값, 아래 마크다운에는 규칙과 이유를 적는다. 모든 규칙은 이 형식이다.

```
- **규칙 한 줄 (구체적인 값으로)**
  Why: 사용자가 말한 이유. 사용자가 말하지 않았으면 "(추정) ..."
```

- "깔끔하게" 같은 모호한 말은 규칙이 아니다. 값으로 바꾼다. (예: "카드 안쪽 여백은 16px, 카드끼리는 24px")
- 작성 후 사용자에게 보여주고 고칠 곳을 묻는다. 승인 후 저장한다.

### 1-4. 에이전트가 읽게 연결
`CLAUDE.md`(Claude Code) 또는 `AGENTS.md`(Codex·Cursor 등)에 아래 한 줄이 없으면 추가한다. 파일이 없으면 만든다. 추가했다고 사용자에게 알린다.

```
UI를 만들거나 고치기 전에 반드시 DESIGN.md를 읽고, 규칙과 다르게 해야 하면 먼저 물어볼 것.
```

## 2. 검사 모드 — 고치지 말고, 보고만

검사하는 쪽이 만든 쪽의 사정을 봐주지 않게 하는 것이 핵심이다.

### 2-1. 가능하면 '다른 AI'에게 맡긴다
서브에이전트(Task/Agent 도구)를 쓸 수 있으면, 이 대화 맥락 없이 `DESIGN.md`와 검사 대상만 넘겨 검사를 맡긴다. "고치지 말고 보고만 하라"고 지시한다. 쓸 수 없으면 직접 하되, 같은 원칙을 지킨다.

### 2-2. 기계 검사: AI 티 나는 패턴
Node.js가 있으면 실행한다.

```bash
npx impeccable detect <검사할 URL 또는 폴더>
```

- [Impeccable](https://github.com/pbakaus/impeccable)의 검사기다. LLM 없이 규칙(62개)으로 AI 티 나는 패턴과 품질 문제를 찾는다.
- 대비·작은 글씨 같은 규칙은 **화면이 그려진 URL**을 검사할 때만 돈다. 로컬 개발 서버나 배포 주소가 있으면 URL을 우선한다.
- 종료 코드 2 = 문제 발견, 1 = 검사 실패. 사용법이 맞지 않으면 `npx impeccable detect --help`로 확인한다.
- 실행할 수 없는 환경이면 건너뛰고, 건너뛰었다고 보고서에 적는다.

### 2-3. 규칙 검사: DESIGN.md와 대조
대상에 맞게 실제 값을 읽어 규칙과 비교한다. 눈대중이 아니라 **측정한 값**으로 판단한다.

- **코드:** 토큰에 없는 hex/rgb 색, 목록에 없는 폰트, 간격 스케일 밖의 값, 규칙에 없는 모서리 값, 금지 패턴을 검색한다.
- **Figma (MCP 연결 시):** 변수에 연결되지 않은 채우기·글자·간격, 분리(detach)된 인스턴스, 라이브러리 밖 컴포넌트를 찾는다.
- **스크린샷만 있을 때:** 확인 가능한 것만 보고하고, 측정이 아닌 추정이라고 표시한다.

### 2-4. 보고서
표 하나로 보고한다. 같은 문제가 여러 곳이면 묶는다.

| 심각도 | 어디 | 지금 값 | 원래 값 | 근거 |
|---|---|---|---|---|
| 높음 | 결제 버튼 배경 | #3B82F6 | color.primary (#2F6BFF) | DESIGN.md 색 규칙 1 |
| 중간 | 카드 안 카드 | 중첩 2단 | 1단 | impeccable detect |

- 심각도: **높음**(규칙 정면 위반·접근성 실패) / **중간**(일관성 깨짐) / **낮음**(다듬기)
- 끝에 "어떤 걸 고칠까요? (예: 1, 3)"라고 묻고 멈춘다. 고치는 건 사용자가 고른 것만 한다.
- 검사에서 반복해서 나오는 문제는 "DESIGN.md에 규칙으로 추가할까요?"라고 제안한다.

## 3. 기억 모드 — 지적 한 번 = 영구 규칙

### 3-1. 이번 세션의 지적을 모은다
- 사용자가 말로 한 지적 ("그 색 아니야", "간격 좁아")
- 같은 잔소리를 두 번 이상 한 것 (가장 중요)
- 사용자가 직접 손으로 고친 부분 (git이 있으면 `git diff`로 확인)
- 사용자가 되돌린(revert) 변경
- 사용자가 "이게 맞아"라고 확인해준 의외의 선택

**제외:** 기능 버그, 이 화면에서만 의미 있는 문구·내용 수정.

### 3-2. 거르고, 일반화한다
- 기준: **다른 화면을 만드는 새 AI도 같은 실수를 할까?** 아니면 규칙이 아니다.
- 다른 곳에서도 막을 수 있는 가장 좁은 수준으로 쓴다. 값과 토큰 이름을 쓴다.
- 기존 규칙과 충돌하면 숨기지 말고 보여준다.

### 3-3. 제안하고 멈춘다
```
이번 작업에서 규칙 후보 3개를 찾았어요.

1. **버튼 사이 간격은 8px**
   Why: "버튼이 붙어 보여" (12:31에 두 번 지적)
2. **본문 폰트는 Pretendard만, 대체 폰트 금지**
   Why: (추정) Noto로 바뀐 걸 직접 되돌리셨어요
3. **카드 테두리 대신 그림자 토큰 shadow.sm**
   Why: "테두리가 답답해 보여"
   ⚠️ 기존 규칙 "카드는 1px 테두리"와 충돌해요

저장할 번호를 알려주세요. (예: "1, 3 저장" / "전부 저장")
(추정)인 항목은 이유를 고쳐주셔도 돼요.
```

### 3-4. 승인한 것만 쓴다
- `DESIGN.md`의 해당 섹션(색, 글자, 간격, 컴포넌트 등)에 추가한다. 맞는 섹션이 없으면 `## 학습된 규칙`에 넣는다.
- 각 규칙 아래에 날짜와 사용자 원문을 HTML 주석으로 남긴다: `<!-- 2026-11-23 · "버튼이 붙어 보여" -->`
- 충돌하는 기존 규칙은 사용자가 고른 쪽만 남긴다.
- 코드로 자동 검사할 수 있는 규칙(예: 특정 hex 금지)은 "다음 검사부터 자동으로 확인할게요"라고 알린다.

---

## 하지 않는 것
- 승인 없이 DESIGN.md에 규칙 쓰기
- 검사·기억 모드에서 화면이나 코드 수정
- 스크린샷 추정을 측정값처럼 보고하기
- "더 모던하게" 같은 취향을 사용자 대신 결정하기
